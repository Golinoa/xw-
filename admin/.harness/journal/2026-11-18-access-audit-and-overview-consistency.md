# 2026-11-18 访问审计 + 总览口径：两个「有功能但没证据」的缺口

## 1. 访问审计（`4adb4aa`）

审计原话是「访问审计不存在」。查下去发现比"忘了写"更根本：**没有任何地方能写**。
`ops.write_audit` 的 actor 取自 `auth.uid()`，而登录那一刻恰好还没有会话
——令牌刚签发、还没被任何请求用过。于是「账号被人登过」这件事在库里查不到。

**解法**：登录成功后，运策端拿**刚拿到的那个令牌**调 `ops.record_access_audit`。
那一刻 `auth.uid()` 就是本人，actor 自然正确。

为什么不让 RPC 收一个 `p_actor_id` 参数：那等于「谁都能替别人写审计」，
比不记更糟。这条在迁移注释里写死了，避免以后有人"顺手"加上。

| 决定 | 理由 |
| --- | --- |
| 只认 `auth.login` / `auth.logout` | 这张表是留痕用的，放开词表等于让人往里灌垃圾 |
| 无活跃运营账号 → `no_operator` 且不写行 | 无 actor 的访问审计没有意义 |
| 失败登录**不记** | 那一刻没有可信身份，记下来的「actor」只能是别人填的字符串；这类事件走请求日志与速率限制 |
| 写审计失败只记日志不抛 | 留痕的可用性不该绑架登录 |
| 登出只在带 Authorization 时记 | 没有令牌就无从归属 |

验证：pgTAP 41 文件全绿（新增 5 条）；登录用例新增 `record_access_audit` 的调用断言
（18 条仍全绿）。踩到的坑：断言「actor 是本人」时先切了 `authenticated`，
而测试账号没有 `audit.read`，RLS 把行藏起来，子查询拿到 NULL，看起来像 actor 没写进去
——读回断言必须在不切角色的情况下做。

## 2. 总览口径（`5da60ad`）

审计原话：「临期权益、开放工单、SaaS 租户、失败同步四项没有与各自列表端点比对的断言，
现有断言只对夹具常数」。这类"看起来有测试"在口径问题上最危险——改了 RPC 口径、
夹具不变，测试照样绿。

新增 `ops_overview_consistency.sql`（5 条）：

- `open_tickets` / `waiting_tickets` → 与**独立 SQL 从 `tickets` 底表复算**比对；
- `failed_sync_commands` → 按「每个映射的最新一条」复算；
- **对照组**：夹具里 2 个映射都有失败命令、只有 1 个最新是失败。实现若写成
  「存在失败命令的映射数」会得到 2，这条会红——这个口径错了数字只增不减；
- 无 `receivable.read` 时 `pending_receipt_amount` 必须**不出现**（不是 0 冒充），
  锁住「看不清」与「真的是 0」的区别。

夹具踩到三个表约束：`waiting` 要求 `waiting_on` 非空、`closed` 要求 `closed_at` 非空、
`failed/succeeded` 要求 `completed_at` 非空。写夹具前先看约束，别猜。

## 3. 边界

- 访问审计只覆盖登录/登出。「读取类」动作（谁看了哪张单）仍未记录：
  那需要给每个读端点都加一次写，量级完全不同，且要先定采样/保留策略。
- 总览口径核对覆盖三个指标（在途/等待/同步失败）+ 一条权限可见性。
  SaaS 租户数与临期权益未做独立复算——它们的底表口径更长，各自需要单独夹具。
