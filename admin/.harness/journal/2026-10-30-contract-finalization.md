## 起点：后端 §14 回执

后端在 `Docs/ops-backend-handoff.md` §14 回了我上一轮的四问，同时指出两件事：

1. 我的顺序建议不成立（`/meta` 不能与 W0.4 并行）；
2. U-18/U-19 **只在 §11 不确定性表，正文没改**。

第 2 条是本轮的主要工作。他说得对：裁决记在附录、正文不动，是三方漂移最常见的起点——
下一个人读 §5.1 只会看到 `items[{id,email,displayName,status,roles,lastLoginAt}]`，

## 我上一轮的顺序建议是错的

我原话是「`/meta` 不依赖 GoTrue，提前与 W0.4 并行」。错在我把它的权限读成「有合法 JWT 即可」，
实际契约写的是「**已认证运营成员**」——要查 `ops.operators` 判成员，表在 T-02a。

所以 `T-02a → T-01 /meta → W0.4 → T-03a /session` 这条链是对的，`/meta` 与 W0.4 不构成并行关系。
教训：判断「某个端点能否提前做」时，只看它调不调 GoTrue 不够，还要看它的**授权前提**依赖哪张表。

## 三个判断的推理

**1. `actor_id` 为什么改成 `actor_user_id`（比对方要求多做一层）**

对方要的是「措辞改为 auth 用户 id」。我改的是列名。理由：注释会过期，列名不会。
审计表已经用 `actor_operator_id` / `actor_user_id` 两列区分两种主体，幂等表若叫 `actor_id`，
两张表的同名列指两个不同的键——排障时按 `actor_id` join `operators.id` 会 join 到空气上。

保留退路：回执里写明「若你已按 `actor_id` 落库，回一句我改回去并加同义注释」。

**2. `scope` 的示例必须改，不是措辞问题**

原文示例 `scope='POST /api/v1/ops/receipts'` 只含方法与路径。幂等键由客户端生成，两个运营成员
之间没有任何协调，撞同一个值时就会共享一个缓存槽——后到者读到他者的响应体。`3df4fe2` 修的
正是这个。契约若原样保留，等于让人把缺陷写回来。

改成「由调用者、组织、方法、路径唯一决定」，拼接还是哈希交给实现。这样 T-02b 想收敛成
`PK(scope, key)` 时也不必再争——语义在契约里已经写死了，形状怎么改都行。

**3. `supportedCurrencies=['CNY']` 接受，但理由要改**

对方的理由写「契约全文只出现 `char(3) DEFAULT 'CNY'`，无多币种需求来源」。这句话与 U-12 冲突：
U-12 明确写「允许 ISO-4217 任意币种，总览按币种分组、不合并」。所以这是**对 U-12 的收窄**，
不是「没有需求」——两者的后续动作完全不同：前者要求端点也按白名单拒，后者什么都不用做。

已写成 U-23，并要求「放开某币种时 `/meta` 与端点校验必须同一次变更」。

## Gitee Go：两条流水线从未执行过

原配置 `triggers.push.branches.precise: [main]`，而所有开发都在 `feat/*` 上。

修复时踩到一个坑，写在 yml 注释里了：**Gitee Go 的不同匹配类别之间是交集**。
官方文档原话「分支匹配的多种规则是交集关系，即同时设置了匹配规则，只有满足所有规则时才可触发」。
所以 `precise: [main]` + `prefix: [feat/]` 不是并集，而是「既是 main 又以 feat/ 开头」= 永不触发。
正确写法是只用 `prefix` 一个类别写多条（同一类别内是并集）：`prefix: [main, feat/]`。

**仍未完成**：推送后还没有在 Gitee 流水线页确认它真的跑起来——命令行看不到 Gitee 侧结果。
另外 `frontend-quality.yml` 末尾的 `quality:check` 含依赖审计，按现有高危 advisory 会红；
那是真实失败，不许通过跳过检查变绿（yml 顶部原有注释已写明这一点，我保留）。

第一次 `pnpm run test:unit` 是 **exit 1**：时长 82s、tests 段 225s，明显被别的进程抢了 CPU
（同时有另一个会话在跑业务端测试/构建）。紧接着两次连跑都是 53/399 全绿、无断言失败。
不隐瞒这条：我没能从那次的输出里看到失败用例名（输出被截断），所以只能按「资源争用导致的抖动」记录，
**不能排除**是 worker 启动超时——这与业务端 A4 那次「静默漏跑」是同一类症状，值得后续留意。

## 前端行为一行没改

契约定稿 ≠ 后端返回。`version` 缺失仍然禁用编辑、字典项缺 `id` 仍然只读，判断逻辑没动；
改的只有提示文案：「契约缺口，等确认」→「已定稿，等后端实现」。

这条值得单独记：**如果这时顺手把禁用逻辑摘了，页面会在真实后端返回之前变成「能点但必然提交失败」**，
比不能点更糟——用户会以为是自己填错了。
