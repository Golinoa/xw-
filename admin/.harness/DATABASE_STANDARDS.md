# 数据库约束

数据库结构、迁移、RLS、SQL 函数和 pgTAP 测试由 `../udone` 唯一维护；此文件约束运营后台的数据库要求，不另设影子 migrations。

- 运营数据使用 Supabase 项目内专用 schema/表；本项目以 `ops` 表示逻辑域，物理命名最终写入 `udone/supabase/migrations/`。
- 迁移使用版本化 SQL；不修改已应用迁移，不通过 Dashboard-only 修改形成不可复现结构。
- 每个暴露对象同时检查 schema 暴露、Postgres grants、RLS、函数 `EXECUTE` 权限和安全 search_path。默认最小权限；每个表均有允许/拒绝用例。
- 运营成员身份从可信 Auth subject 与服务端维护的运营成员/角色记录推导；不信任用户可编辑 profile。
- 业务完整性使用 NOT NULL、CHECK、UNIQUE、外键、索引与事务；状态、金额、幂等键等不变量不能只由前端保证。
- 列表和总览按已知过滤/联接/排序路径设计索引；分页查询避免 N+1 和无界扫描。索引基于需求或数据证据，不因猜测堆叠。
- 钱款使用精确 decimal/numeric，合同内不混币种；时间戳使用 timestamptz，日期字段遵循 PRD 定义。
- 合同/收款/退款/授权等历史使用追加式事件、版本或冲正；默认限制删除，不级联清除审计和账务历史。
- 多实体业务命令通过同一事务/RPC或等价事务保证原子性；并发核销、重复开通、重复退款须由唯一约束/版本控制/幂等控制处理。
- 数据库变更需在 `udone` 本地环境验证 schema、权限、RLS 和事务测试；绝不对共享/生产数据库运行 reset。
