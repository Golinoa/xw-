### 踩坑：本机 git 大批量写工作区会被中断（重要）
- `git merge` / `git checkout -- .` 一次写上千文件时会中途被杀：退出码 1、无输出、留下 `.git/index.lock`、工作区出现大批 `D`（文件先被 unlink 再写，死在中间）。
- **可靠做法（本次验证有效）**：
  1. 只在索引里合并，不碰工作区：`git merge-tree --write-tree --no-messages HEAD <branch>` 拿结果树（真正三方内容合并，只有真冲突）；
  2. 临时索引 `GIT_INDEX_FILE=.git/merge-idx` → `git read-tree <tree>` → 冲突用 `git update-index --cacheinfo 100644,<blob>,<path>` 换掉 → `git write-tree`；
  3. `git commit-tree <tree> -p A -p B -m ...` → `git update-ref refs/heads/main <commit> <old>`；
  4. `git reset --mixed HEAD` 同步索引，再用 `git diff --name-only -z | xargs -0 -n 12 git checkout --` **分批**落盘（每批 ≤15 个文件，一次就过）。
- 注意 `git read-tree -i -m base ours theirs` 只做简单合并，会把两边都改过的文件全报冲突（本次误报 49 个），不能代替 `merge-tree`。
- 合并后 `git status` 出现的 `??` 文件，可能是被合掉的旧文件残留在磁盘上（不是 git 的问题），需按 `cat-file -e` 逐个确认后再删。

### 🔴 本机三条硬坑（下次直接照做，别再试错）
1. **`NODE_OPTIONS` 注入了 `genie-safe-delete.cjs`**：它把 Node 的所有删除改成「进回收站」，
   而这台机器回收站 API 失败（"Some operations were aborted"）⇒ 任何 Node 程序删文件都报
   `[safe-delete] 操作失败`。**凡是要删文件的命令，前面加 `env -u NODE_OPTIONS`**。
   `pnpm typecheck / install` 都必须这样跑。
2. **批量删除保护**：`CODEBUDDY_SAFE_DELETE_BULK_GUARD`，阈值 **8000 个/轮**，超了之后本轮
   所有删除都 fail-closed（EPERM，连新建的空文件都删不掉，`icacls /reset` 无效）。
   状态在 `%TEMP%\codebuddy-safe-delete-bulk\<hash>\state.json` + `signal-call_*.json`。
   本次就是 `rm -rf node_modules`（10017 个文件）触发的 ⇒ **不要整目录 rm -rf node_modules**，
   要么分批，要么让 pnpm 自己 purge。
3. `pnpm install` 需要 `CI=true`（否则 no-TTY 中止）+ `env -u NODE_OPTIONS`；
   仍会因 `_tmp_<pid>_<hash>` 残留文件删不掉而中止（那些文件是上一次崩溃留下的 0 字节硬链接）。
4. 🔴🔴 **最坑的一条（2026-11-15 挖出来的）**：`TaskStop` 杀掉 pnpm 后台任务时，**每次都留 2 个孤儿进程**
   （`pnpm.mjs install ...`），它们占着 `D:\.pnpm-store\v11\index.db` 的 SQLite 写锁 ⇒
   **之后每次 install 都静默卡在 added 17/41/45/70 不动，日志十分钟不写一行**，看起来像「环境坏了」。
   一次被杀后累计 10 个孤儿。查杀方式（`ps` 看不到，必须用 Win32_Process）：
   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -like '*pnpm*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
   Remove-Item 'D:\.pnpm-store\v11\index.db-shm','D:\.pnpm-store\v11\index.db-wal' -Force
   ```
   ⇒ **杀掉 pnpm 后必须清孤儿+清锁，否则下一次一定「卡死」**。同理 `rm` 报 "Device or resource busy" 也是这帮孤儿。
5. **大 tarball 写入报 `error (23)`**：`ant-design-vue@4.2.6`、`@cloudflare/workerd-windows-64`
   两个包稳定失败，换 npmmirror / registry.npmjs.org 都一样 ⇒ 不是网络，是大文件写入被拦。
   其余 355 个包全部复用成功。两者都不在测试链路（测试只要 vitest/hono/zod）。
6. 结论：**JS 依赖别在沙箱里装**，让用户在普通终端跑 `pnpm install --frozen-lockfile`；
