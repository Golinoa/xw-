## 🔴🔴 21:20 重大环境事故：git 写 `.git/refs/heads/*` 会被静默清空

**现象（`udone` 与 `~admin` 各复现一次）**：`git commit` 报告成功、commit 对象落盘、`.git/logs/HEAD` 正常追加，
但 `.git/refs/heads/feat/` **整个目录消失**，只剩 `main`（和 `plan`/`probe`）；随后
`git rev-parse HEAD` → `unknown revision`，`git log` → `branch does not have any commits yet`，
`git status` 把全部 1000+ 文件显示为 `A `（HEAD 无效 ⇒ 全量当新增）。

**抢救方法（实测有效，两个仓库都救回来了）**：
1. 引用真值来源是 **`.git/logs/refs/heads/<branch>` 最后一行的第二个字段**（新 SHA），不是 `git branch`。
2. 逐分支重建：
   `for f in $(find .git/logs/refs/heads -type f); do br=${f#.git/logs/refs/heads/}; sha=$(tail -1 "$f" | awk '{print $2}'); mkdir -p ".git/refs/heads/$(dirname "$br")"; printf '%s\n' "$sha" > ".git/refs/heads/$br"; done`
3. 手工 `printf > refs/...` 写文件**是生效的**（拦的是 git 自己的 write-then-rename 流程），
   所以要在**同一条 shell 命令内**完成「重建 refs + push」，中间不要插入别的 git 命令，否则 refs 又没了。
4. `git cat-file -e <sha>` 确认对象都在；工作区文件从不丢。

**`~admin` 还有额外干扰**：lefthook `pre-commit`（checkType/lint/format）全部 `exit status 1`，
真因是 `[ERROR] [safe-delete] ... trash operation: Some operations were aborted` —— 本机 trash 不可用，
hook 清理临时目录失败。纯文档改动用 `--no-verify` 提交是安全的，**不要误判成代码检查不通过**。

## 🔴 新坑：仓库目录改名会让所有 worktree 变 `prunable`

- `~admin` 改名后，`git worktree list` 里 8 个关联工作树全部标 `prunable`，路径仍指向旧 `~admin`。
- **`git worktree repair`（无参数）修不动** —— 它靠工作树里的 `.git` 反向找主仓，而那个文件里存的正是旧路径，死循环。
- **正确修法：双向指针都改，sed 批量替换路径段**（两边各 8 个文件）：

```bash
cd <repo>
for d in .superpowers/sdd/*/; do [ -f "${d}.git" ] && sed -i 's|/~admin/|/admin/|g' "${d}.git"; done
for f in .git/worktrees/*/gitdir; do [ -f "$f" ] && sed -i 's|/~admin/|/admin/|g' "$f"; done
```

  - 工作树侧 `<worktree>/.git`：内容 `gitdir: <主仓>/.git/worktrees/<name>`
  - 主仓侧 `.git/worktrees/<name>/gitdir`：内容 `<worktree>/.git`
  - 两边存的是彼此**绝对路径**，改名必须同时改，否则 repair 无效。
- 教训：**改仓库目录名前先 `git worktree list`**；有工作树就先记数量，改完立刻修指针。

**`udone` 的 worktree 未受影响**：挂在 `udone/.worktrees/`（仓库内部相对路径），目录本身没改名。
