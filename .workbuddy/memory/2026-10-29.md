## 工具链：Node 版本冲突是本次主要坑

| 项目 | packageManager | engines.node | 结果 |
|---|---|---|---|
| `udone` | pnpm@11.24.0 | 无约束 | 任意 Node 可跑 |
| `admin` | pnpm@10.33.4 | **24.20.0 精确**，且 `.npmrc` 里 `engine-strict=true` | 必须 Node 24.20.0 |

- 机器自带 Node 是 WorkBuddy 托管的 22.22.2（`~/.workbuddy/binaries/node/versions/22.22.2-6`），**不在系统 PATH**。
- 用 22 跑 admin 直接 `ERR_PNPM_UNSUPPORTED_ENGINE`，报 `Expected version: 24.20.0`。
- **解法**：从 npmmirror 下载 `node-v24.20.0-win-x64.zip`（35.8 MB）解压到 `D:\MYC\A.soft\nodejs-24.20.0`，**用 unzip 而非 Expand-Archive**（快得多）；给 node24 单独装 pnpm 11.24.0。
- **PATH 顺序**：`node24; node22(WorkBuddy); Git\cmd; WindowsApps`。node24 在前，用户终端默认拿到 24；admin 与 udone 都能跑（udone 无版本约束）。

**为什么不能只留一个 node**：pnpm 的 `.cmd` shim 优先用同目录的 `node.exe`，所以 pnpm 装在哪套 Node 下就决定了它跑在哪个 Node 上——必须在 node24 目录里另装一份 pnpm，否则 pnpm 仍以 node22 运行，engine 检查照样失败。

**pnpm 版本协商是可用的**：在 admin 目录执行 `pnpm -v` 会自动协商成 10.33.4（pnpm 的 `manage-package-manager-versions` 默认开启），无需手动切换。

**npm 源**已全局设为 `https://registry.npmmirror.com/`（npmjs 可达但 8.5s 才响应，镜像 1.8s）。
