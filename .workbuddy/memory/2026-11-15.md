## 🔴 依赖装不上的真因（2026-11-15 13:50 更正，此前的结论是错的）

**不是沙箱限制，也不是删除保护，是 pnpm 的下载超时。** 用户双击跑了两次都失败，才逼出实测：

| 实测 | 数值 |
| --- | --- |
| 本机到 registry 速度 | 约 640 KB/s（npmmirror CDN 677 / npmjs 604，两源都能下） |
| `workerd-windows-64` | 34.5 MB → 单独下 54 秒 |
| pnpm 默认单项超时 | 60 秒 |
| pnpm 默认并发 | 16 路 ⇒ 每流约 40 KB/s，10 MB 的 esbuild 要 250 秒 |

⇒ 所有大包在 60 秒被掐，报 `error (23)` / `TimeoutError`。失败的永远是同一批大包
（esbuild / workerd / typescript / prettier / playwright-core / miniflare），小包从不失败。
**换源无效是必然的**：两源速度一样，问题不在源。

修复：`--fetch-timeout=600000 --network-concurrency=4 --fetch-retries=5`，外面再套最多 3 轮重试
（store 累积，重跑接着上次进度）。
⚠️ `--config.network-concurrency=4` 不能用，会被解析成两级配置 `network.concurrency`，
报 `Expected concurrency to be a number from 1 and up, got 4 (string)`；必须写显式 `--network-concurrency=4`。

**教训**：「换源无效」只能排除源，不能推出「写入被拦」。中间还有一个没被测的变量——单请求超时。
以后遇到"某几个包稳定失败、其他都成功"，先看**失败包的体积分布**，那是超时的指纹。

### 🔴 数据库层的新坑（通用）：RLS 策略 ≠ 表权限

`authenticated` 对 `customer_sources` 只授了 `select/insert/update`，**没授 `delete`**。
只加 `CREATE POLICY ... FOR DELETE` 时，删除报的是
**`permission denied for table customer_sources`（硬报错，不是 0 行）**，接口层会当 500。
⇒ **加删除能力必须两件事一起做：`GRANT DELETE` + `CREATE POLICY ... FOR DELETE`。**
⇒ pgTAP 要专门断言「无写权限时返回 0 行而不是报错」，这一条同时验证两件事。
