## 续：修复 E2E runner「双版本冲突」遗留（部分解决）

上一批报的「two different versions of @playwright/test」**诊断错了**，实际不是版本冲突：

- 证据：`@playwright/test@1.64.1` 内嵌 playwright 1.64.1，顶层 `playwright@1.60.0`；
  但用 `node node_modules/@playwright/test/cli.js test --list` 能正常列出全部 33 条用例，
  `auth.e2e.ts` 用同一 runner **5/5 通过（42s）**。所以 runner 本身没坏，不需要动 node_modules。
- 之前「零输出 exit 1」是我用 `| tail` 管道 + 混用 `.bin/playwright` 造成的调用问题。
  **正确调用**：`cd apps/web-antd && PLAYWRIGHT_CHANNEL=chrome node ../../node_modules/@playwright/test/cli.js test <file> --reporter=line`，
  且必须用 `run_in_background`（前台管道会吞输出/卡住）。
- 真凶是我写的 6 条 E2E 里**桩字段不合法**，页面拿到坏数据不渲染，expect 一直等：
  - `listTourists` 响应是 `{ roster: {...} }` 包一层，不是扁平；且 roster 需要 personCount。
  - `leadSchema` 的 nullable 字段（wechat/email/source/... 十几个）都必须显式出现，缺一个就契约失败。
  - 修法：对照 `scripts/mock-fixtures.json`（由契约 schema.parse 自检通过）核字段，不要手猜。
- 6 条用例修完后**都执行到了**（日志出现 [1/6]..[6/6]），无任何失败报告；
  但 runner 在本机卡在 worker teardown（`worker-0 process did not exit within 300000ms`），
  **没能打印 "6 passed" 汇总**。所以只能说「6 条都跑到且无失败」，不能说「全绿」。
- 另一个环境坑：`taskkill` 杀掉 5330 后立即跑 E2E，新 runner 会卡在 webServer 启动（日志空）。
  要等端口自然释放，不要在命令里连着杀端口。
