# 旅行社 OMS 复刻详细需求

版本：2.2；日期：2026-10-05；状态：开发基线。

本文件把 [唯一真源](REPLICATION_SPEC.md) 转成可设计、开发和验收的产品需求。目标站事实、字段取值、接口证据和补测完成度只在唯一真源维护；若本文与真源冲突，以真源为准。

## 1. 产品目标与边界

系统服务旅行社内部员工，覆盖线索、客户、基础资料、订单、游客、应收应付、收付款申请、逐级审批、结算、余额、经营分析和审计。订单详情是业务聚合中心；附件上传/下载不进入首期范围。

首期不包含真实银行划款、第三方支付、外部消息发送、OTA 下单、电子合同签署和多币种核算。系统只记录内部业务和财务状态；任何外部集成都必须作为独立范围重新确认。

## 2. 用户、租户与权限

### R-AUTH-01 登录与会话

- 用户使用经验证的邮箱和密码通过 Supabase Auth 登录；邮箱是全局身份标识，不建立用户名映射或用户名登录。显示名称独立保存在 profile。
- 邀请发往邮箱。受邀者完成 Supabase Auth 邮箱验证并接受邀请后，才获得对应组织成员权限；匿名和错误响应不得泄露邮箱是否已注册。
- 忘记密码使用 Supabase Auth recovery email。请求页面对已注册和未注册邮箱显示相同确认；密码重置成功后按 Auth provider 规则撤销 refresh session。已签发的无状态 access JWT 最迟在其有效期结束时失效；停用组织成员则由 Worker 每个受保护请求即时复查 active membership 并拒绝。
- 登录失败使用通用错误；只记录认证提供方支持的失败事件/次数，不记录密码、token 或其他认证秘密，不自行增加按账户锁定。部署应配置 Supabase Auth IP 限流与 CAPTCHA；浏览器直接调用 Auth，以保留真实客户端 IP。
- 退出和密码重置的会话撤销、过期行为遵循 Supabase Auth。所有写操作校验服务端会话、组织、角色权限和数据范围；登录失败/成功、退出、密码重置以及成员生命周期事件保留可审计记录。
- 所有写操作校验服务端会话、CSRF、租户和功能权限。
- 登录、退出、失败登录、密码修改和高风险操作进入审计日志。

### R-AUTH-02 角色与数据范围

- 基础角色包含公司管理员、计调员和财务；权限按功能动作授予。
- 功能权限与数据范围分开建模。数据范围至少支持本人、全部，后续可扩展部门；本期默认映射为管理员全部、计调员本人、财务全部（限已授权财务功能），并由 API 与 RLS 强制执行。该默认是实现裁定；目标系统同角色本人/全部范围尚无验收证据，不作为目标事实。
- 待审批任务按当前审批级次、角色及指定审批人计算。
- 是否允许审批自己创建的申请必须是显式配置。目标租户当前允许管理员终审自己创建的申请，复刻不能把“全面禁自审”写死。

### R-TENANT-01 租户隔离

- 所有业务表、附件、导出、统计和后台任务必须带租户上下文。
- 服务端拒绝跨租户 ID、关联对象、文件路径和导出访问；前端隐藏不能代替服务端校验。
- 租户隔离验收在测试准备阶段创建至少两个虚构租户及各自角色数据，并执行跨租户正反向访问测试。

## 3. 基础资料

### R-CUSTOMER-01 客户

- 支持新增、查看、编辑、筛选和关联订单。
- 核心信息包括姓名、电话、邮箱、证件、生日、来源、标签和备注。
- 电话、证件等敏感字段在列表按权限掩码；掩码值不得覆盖原值。
- 同租户按规范化手机号提示疑似重复，不自动合并或覆盖客户资料；操作者明确选择关联既有客户或继续创建。
- 订单表单允许快捷新增客户，成功后自动选中新客户。

### R-MASTER-01 标签、来源与字典

- 客户标签支持名称、颜色、新增、编辑、删除及客户关联。
- 客户来源支持树形层级和停用；历史单据保留名称快照。
- 付款方式、线路类型、供应商类型、出发城市和地区均由公司维护。
- 被历史业务引用的字典项优先停用；删除需做引用校验。

### R-SUPPLIER-01 供应商

- 支持类型、名称、联系人、电话、结算方式、状态和备注。
- 月结与非月结属性参与结算筛选。
- 被订单或财务记录引用时不得直接物理删除，并返回具体引用原因。
- 订单表单允许快捷新增，成功后自动回填。

### R-ROUTE-01 线路

- 支持名称、线路类型、地区、出发城市、天数、自组团属性、启停和备注。
- 订单可选择线路，也可在表单内快捷新增。
- 历史订单保留线路名称和关键属性快照，避免字典改名破坏历史展示。

## 4. CRM

### R-CRM-01 线索

- 字段包括姓名、手机/微信、邮箱、来源、目的地、出发城市、出游类型、意向程度、期望日期、预算上下限、成人、儿童和备注。
- 姓名、联系方式、来源、目的地、出发城市、出游类型、意向、期望日期及预算按目标表单校验。
- 阶段至少包含新线索、需求沟通、报价中、方案确认、已成单、已放弃。
- 支持负责人、下次跟进时间、跟进内容、阶段变化和完整时间线。
- 跟进与阶段变更追加历史事件；报表按创建时间 cohort 统计阶段转化，漏斗展示这些线索当前阶段分布。

### R-CRM-02 公海与转换

- 支持进入公海、认领、分配、超时回收和权限控制。
- 无有效跟进满 7 个自然日进入超时回收；系统每日检查，认领和回收用版本条件保证同一线索不会并发归属给多人。
- 线索可转客户，并可继续创建订单；重复客户需提示并允许关联既有客户。
- 转换必须幂等，不得重复生成客户或订单。

目标站当前 `POST /leads` 在完整字段提交时返回 500；该状态只描述目标站证据。本项目按上述转化规则实现 CRM 成功链，并通过幂等、权限和重复客户场景验收，不复制该缺陷。

## 5. 订单

### R-ORDER-01 新建与编辑

- 订单类型为正式订单或预订单，服务端值采用 `active`、`booking`。
- 表单分为客户与人数、线路与团期、基础应收、其他应收、基础应付、其他应付和金额摘要；文件关联按 R-FILE-01 延后。
- 人数 = 成人 + 儿童；出团、回团日期需满足业务顺序。
- 支持多条其他应收和应付；应付行必须关联供应商。
- 金额使用十进制，服务端重新计算合计与利润，不信任前端总计。
- 利润 = 应收合计 − 应付合计；毛利率和客单价按真源第 4 节统一计算。

### R-ORDER-02 状态机

- `booking` 可确认出团为 `active`；`active` 可转回 `booking`。
- `active` 可锁团为 `completed`；锁团后编辑受限，解锁必须填写原因并回到 `active`。
- 可取消的订单进入 `cancelled`，恢复后回原业务状态。
- 已存在任何收付款申请时禁止取消订单；先驳回或撤回相关申请，再执行取消。
- 首期不自动生成 `to_lock`；仅支持用户按权限手工锁团和解锁。

### R-ORDER-03 列表、日历、对账与回收站

- 列表支持关键词、日期字段、日期范围、状态和更多业务条件筛选，并展示金额、未收未付、利润和创建人。
- 日历按出发、回团事件展示，可切年月和过滤条件。
- 订单可确认对账和取消对账；对账标记不改变订单业务状态。
- 批量删除只移入回收站。恢复必须经过操作密码二次校验；彻底删除需更高权限、明确影响且默认关闭。
- CSV 导出继承当前筛选和数据范围，敏感字段按权限处理。

## 6. 游客与附件

### R-TOURIST-01 游客名单

- 支持逐行维护姓名、手机、证件类型、证件号、成人/儿童、年龄、性别和备注。
- 支持下载模板和 CSV 导入；导入默认追加，必须提供覆盖/追加的明确提示。
- 导入前展示解析结果、错误行和差额。目标站人数不一致只警告仍可保存，复刻可保留该行为，并在订单详情持续显示差额。
- 同一订单按证件类型和规范化证件号去重；证件号为空时不自动合并。重复证件、非法日期、缺列、编码错误均使整批拒绝，返回逐行错误，不产生部分写入。

### R-FILE-01 文件

- 对象存储目标选型为七牛云。当前尚无经确认的前端文件上传/下载业务流程，因此七牛云集成暂缓，不属于当前前端或 API 开发范围。
- 触发条件：产品需求明确出现需持久化的文件上传或下载流程后，另立执行任务，确认业务入口、授权生命周期和验收条件，再设计集成。仅用于解析且不持久化的导入文件不自动触发对象存储集成。
- 在该任务获批前，不实现七牛 SDK、上传 UI/API、签名 URL，也不假设凭证名称、接口或已完成的验收。
- 合同和收付款凭证支持 PDF，图片格式和大小上限按最终配置确定。
- 文件存储使用不可猜测对象键；下载通过授权控制器或等价签名 URL，不直接暴露公共目录。
- 未登录访问必须跳转登录或返回 401/403；登录后还必须校验租户和对象权限。
- 文件元数据记录租户、业务对象、原始名、MIME、大小、上传人和时间。

## 7. 应收、应付与申请

### R-FIN-01 财务项目

- 订单保存后生成可追踪的应收、应付项目，每项包含原始金额、已确认金额、在途金额和可申请余额。
- 同一供应商的不同应付项目独立追踪；历史名称和金额不得随主数据修改而漂移。
- 可申请余额在事务内校验，防止并发超额。

### R-FIN-02 收款申请

- 选择订单及具体应收项目，填写金额、方式、日期、流水号、凭证和用途备注。
- 金额不得超过该项目剩余可收；服务端返回可理解的项目级错误。
- 待审申请占用额度但不计入已收；驳回释放额度；终审自动确认后计入已收。

### R-FIN-03 付款申请

- 选择订单、供应商及具体应付项目，填写金额、方式、账户、日期、凭证和备注。
- 支持部分付款；额度、状态和金额规则与收款保持对称。
- 系统只记录付款事实，不直接发起银行转账。

## 8. 审批

### R-APPROVAL-01 流程配置

- 收款和付款可独立配置一至多级审批；每级指定角色或人员。
- 配置包含终审后自动确认、是否允许撤回、是否允许同人审批自己的申请。
- 在途实例保存流程快照；修改配置不得静默改变既有实例。

### R-APPROVAL-02 状态与动作

- 申请依次进入财务和管理员待审；每次审批记录级次、操作者、时间、意见和前后状态。
- 驳回必须填写原因；创建人编辑、回复并重提后，从产品配置的级次重新开始。目标站本轮从财务级重新开始。
- 终审自动确认后更新已收/已付和账户余额。
- `undo-approve` 撤回终审时回滚确认金额，并回到终审待办；已完成的前级审批保留。
- 所有状态迁移使用事务、幂等键或版本号，避免双击和并发重复记账。

## 9. 结算、余额与报表

### R-SETTLE-01 批量结算

- 按供应商、结算方式和应付项目选择待结算项，录入日期、方式和金额。
- 提交前二次展示明细；已纳入或余额不足的项目不得重复结算。
- 结算周期为自然月，可合并同供应商的跨订单应付明细；每条应付明细只能进入一个已确认结算批次。结算批次只锁定待结算额度，实际付款单独走付款申请和审批，不重复生成付款流水。

### R-BALANCE-01 账户余额

- 每个付款方式可映射资金账户；余额 = 期初 + 已确认收款 − 已确认付款。
- 审批中和已驳回申请不改变实际余额；终审撤回同步回滚。
- 余额调整必须用不可变更的调整流水，并记录原因和权限。

### R-REPORT-01 报表

- 经营分析包含总览、订单明细和供应商统计；业绩支持本人/全部范围。
- 经营报表首期统一以订单创建日期过滤，并在页面显示“创建日期”；供应商统计沿用相同订单范围。
- 默认统计包括预订单、进行中和已锁团订单，并分状态展示；取消订单默认排除，可通过状态筛选显式纳入。财务统计只计已确认流水，待审金额单独展示为在途金额。
- 报表、仪表盘、导出使用同一统计服务或口径函数，避免数字不一致。

## 10. 通知、审计和系统设置

### R-NOTIFY-01 站内通知

- 生成审批待办、驳回、临期、出团和跟进提醒；支持未读计数、已读和对象跳转。
- 外部短信、邮件和企业微信不在首期范围。

### R-AUDIT-01 审计

- 记录操作者、租户、时间、IP/设备摘要、对象、动作、结果和必要的变更摘要。
- 密码、Cookie、Token、完整证件号和附件正文不得写入日志。
- 订单状态、金额、审批、权限、配置和删除恢复属于强制审计动作。

### R-SETTING-01 公司配置

- 管理公司资料、主题、字号、业务字典、审批和订单规则。
- 设置保存需版本化并保留审计；Logo 上传不属于首期范围。
- 影响财务或权限的配置需要操作密码或二次确认。

## 11. 非功能需求

- 金额和审批写入必须事务一致，关键命令可重试且不重复记账。
- 列表和报表按租户、权限、日期和状态建立可验证索引；常用列表在目标数据量下保持交互可接受。
- 使用结构化日志、错误追踪、审计和备份恢复；业务错误返回中文可行动提示。
- 秘密仅进入安全配置，浏览器和日志不得泄漏 Cookie、CSRF、密码或个人敏感数据。
- 桌面端为主要工作界面；窄屏至少保证查看、搜索和审批可用，视觉基线需另补截图确认。
- 所有时间持久化为统一时区基准，界面按公司时区展示；本项目当前业务时区为 Asia/Shanghai。

## 12. 发布验收门槛

1. 新建预订单、确认出团、转回预订单、锁团和解锁形成可回放状态链。
2. 多应收应付金额和利润服务端重算，超额及并发申请被拒。
3. 收款、付款均跑通驳回重提、两级审批、自动确认和终审撤回。
4. 游客手工录入、CSV 有效/无效文件、追加和人数差额都有明确结果。
5. 合同与凭证的未登录、同租户无权、同租户有权和跨租户访问验收，待 R-FILE-01 触发并定义流程后纳入独立交付验收；当前不阻塞核心流程。
6. CRM 跑通线索、跟进、公海、转客户及转订单；不接受目标站当前 HTTP 500 行为。
7. CSV 导出继承筛选和权限；仪表盘、报表、余额与订单详情数字一致。
8. 订单回收站恢复、关联保护和审计通过；生产默认禁止彻底删除。
9. 停用账号、本人/全部范围、角色权限、租户隔离均有服务端负向测试。
10. 备份恢复、错误追踪、关键审计和敏感信息扫描通过。

## 13. 首期范围与默认决策

工程框架、API 运行时、数据库和应用部署方案见 [TECH_SELECTION.md](TECH_SELECTION.md)。业务默认值见第 25 节；容量验收采用[模块化与高性能架构方案](../.harness/docs/design-docs/functional-modular-architecture.md)第 9 节固定工程基线：2 个租户，每租户 20 个成员、10,000 个订单、100,000 条游客记录、50,000 条财务/审批/审计记录，并模拟每租户 20 个活跃用户。该数据剖面用于测试，不代表目标站或真实客户规模；免费配额不满足时先升级资源再验收。

首期包含 CRM、站内通知和系统内财务记录/审批；不包含 AI 解析、外部消息、银行支付/转账、附件上传下载、提成和自组团专项分析。文件能力不阻塞当前阶段，也不设置本期文件格式、大小或存储容量指标。规模增长通过第 22 节告警阈值和性能目标触发资源升级，不要求预先预测客户规模。

## 14. 前期部署策略决定（2026-10-02；对象存储于 2026-10-03 修订）

前期采用“零自购服务器的托管云试运行”模式：Cloudflare 部署 Web 前端和 API，Supabase 提供 PostgreSQL 与认证，七牛云为对象存储目标。公司多人通过公网访问。暂不购买服务器和域名，先使用平台默认域名；域名只影响访问地址，不影响系统能力。当前尚无经确认的前端文件上传/下载流程，七牛云集成暂缓；该流程进入产品需求后另立执行任务。技术选型文档已同步该存储决策。

### 14.1 公司多人使用的确定方案

- 前期使用场景确定为公司多人协作，不按个人演示项目设计。
- 员工可在办公室、家里或手机网络通过 HTTPS 登录，不依赖办公室电脑持续开机。
- 首期不购买域名，使用 Cloudflare 默认域名；需要品牌地址时再绑定自有域名。
- 试运行数据遵循最小化原则：仅录入工作所需信息，证件号等高敏感字段在完成跨租户、权限、备份和恢复验收前不得批量导入。
- 每日从现有服务器执行数据库活动检查及加密备份；至少保留 7 个每日备份和 4 个每周备份，并每月实际恢复一次。
- 超出免费额度、访问稳定性不能满足团队需要，或进入正式运营时，按本节升级路径迁移，不改变业务数据库模型。

因此前期采购结论为：无需购买服务器，域名也不是上线前置条件；现有服务器只承担健康检查和备份，不承载主业务。

云端多人试运行环境采用：

- Web 静态资源和轻量 API 部署到 Cloudflare Workers；使用免费 `workers.dev` 域名即可开始。
- 业务数据库和登录认证使用 Supabase Free 的 PostgreSQL/Auth。
- 对象存储目标为七牛云；文件上传/下载已排除在首期范围之外，不开发存储集成或文件入口。
- 定时提醒使用 Workers Cron Triggers；复杂财务写入封装为单次 PostgreSQL 函数/RPC，保证事务一致性。
- 数据库结构由迁移文件管理，不依赖 Supabase Dashboard 手工配置；首期不提供文件访问授权或传输接口。
- Supabase Free 没有自动备份，试运行期也必须安排加密 `pg_dump` 到独立存储，并定期验证恢复。

该方案的当前免费边界：Workers Free 为每日 100,000 请求、每次调用 10 ms CPU；Supabase Free 为 500 MB 数据库、5 GB 出站流量、两个活动项目，连续一周无活动会暂停且不提供自动备份。七牛云不进入首期，不纳入当前套餐、容量或成本假设。

Supabase Free 防暂停措施：在数据库中建立不含业务数据的单行健康检查表，只允许读取；由现有服务器每天定时通过 Supabase REST API 查询一次，并在请求失败时告警。URL 和访问密钥只能通过服务器环境变量注入，不写入仓库或日志。Supabase 官方说明过去一周每天少量用户数据库查询通常足以避免自动暂停，API/应用请求都可产生该活动；但免费计划仍没有不暂停 SLA，因此同时保留项目暂停邮件通知和人工恢复预案，正式运行时升级 Pro。

中国大陆网络边界：Cloudflare 官方说明境外节点面对大陆用户存在明显延迟和可靠性问题，中国网络仅作为 Enterprise 单独订阅；Supabase 当前没有中国大陆区域，首选新加坡并实测团队网络。免费云环境属于试运行方案，不承诺生产 SLA；出现持续超时、丢包或业务中断时立即执行国内云迁移预案。

Vercel Hobby 不用于该 ERP 的真实业务试运行，因为其官方公平使用规则限定为个人、非商业用途。若只做无真实业务数据的界面演示，可以临时使用。

海外或跨境场景的升级顺序为：先升级 Supabase Pro 获得不暂停和自动备份，再在 Workers 免费 CPU/请求不足时升级 Cloudflare Workers Paid。大陆正式运营则迁往国内托管 PostgreSQL、对象存储和应用运行服务。后续如需私有化，保持 PostgreSQL、S3 兼容对象接口和标准迁移文件，可迁往 VPS 或私有云。

这项部署决定意味着首期后端应使用适合 Workers 的 TypeScript 运行时，避免选择依赖常驻 PHP/Java 进程的方案。前端已采用 Vue 3、TypeScript、Vite 和 Ant Design Vue，具体技术边界见 `Docs/TECH_SELECTION.md`。

## 15. 开发基线与需求优先级

本节起为新系统的开发约束，不声称是目标站内部实现。开发人员必须同时查阅唯一真源的字段字典、状态证据和补测结论。

- **P0**：首期上线必须具备，缺失会阻断核心订单或财务链路。
- **P1**：多人试运行必须具备，可在核心链跑通后交付。
- **P2**：增强能力，允许排到试运行反馈后。
- 每个需求使用本文 `R-*` 编号追踪；代码提交、测试名称和验收记录引用对应编号。
- 未明确的业务规则按第 25 节默认决定实现，不允许开发人员自行猜测目标站行为。

首期范围：P0 包含认证租户、客户与基础资料、订单、游客、应收应付、收付款申请、两级审批、余额、审计和备份；P1 包含 CRM、回收站、导出、通知和基础报表；P2 包含 AI、复杂提成、外部消息和第三方集成。文件存储集成不因“首期附件”这一概念性范围自动启动；须先有明确的前端上传/下载流程，再另立执行任务。

## 16. 角色与权限开发规格

### 16.1 公司管理员

- 管理公司资料、用户、角色、权限、字典和审批配置。
- 查看公司全部客户、订单、财务、报表和审计数据。
- 执行管理员级审批、终审撤回、订单恢复和高风险配置。
- 不得读取其他租户数据；平台管理权限不属于公司管理员。

### 16.2 计调员

- 管理权限范围内的线索、客户、供应商、线路、订单、游客和附件。
- 创建收付款申请，查看本人或获授权订单的财务进度。
- 默认不能管理用户、角色、审批配置、账户期初或执行终审。

### 16.3 财务

- 查看授权范围内订单的应收应付，创建或审核收付款申请，查看余额与财务报表。
- 默认不能修改订单业务内容、客户证件、用户角色或公司配置。
- 财务审批只能处理当前轮到财务级且未被其他人完成的实例。

### 16.4 权限判定顺序

每次请求依次校验：有效会话 → 有效租户 → 账号启用 → 功能权限 → 数据范围 → 对象租户归属 → 对象当前状态。任一步失败均不执行写入；返回 401、403、404 或 409 时不泄漏对象是否存在于其他租户。

前端菜单和按钮按权限隐藏，但所有限制必须在服务端重复校验。批量接口逐项验证租户与权限，禁止只检查第一个对象。

## 17. 领域模型与数据约束

### 17.1 核心实体

- `tenants`：公司、时区、服务状态和配额。
- `users`、`roles`、`permissions`、`user_roles`：身份与功能权限；用户状态保留历史，不物理删除审计关联用户。
- `customers`、`customer_sources`、`customer_tags`：客户档案、来源树和标签。
- `suppliers`、`routes`、`regions`、`business_dictionaries`：供应商、线路、地区和公司字典。
- `leads`、`lead_followups`：CRM 线索、负责人、阶段和跟进历史。
- `orders`、`order_receivables`、`order_payables`：订单主表及应收应付项目。
- `tourists`、`attachments`：游客与未来文件流程的元数据；文件表及关联在 R-FILE-01 触发后再设计和落地。
- `payment_requests`、`approval_instances`、`approval_steps`、`approval_actions`：收付款申请与审批快照。
- `ledger_entries`、`fund_accounts`：确认后的不可变资金流水和账户余额来源。
- `notifications`、`audit_logs`、`system_settings`：站内通知、审计和配置版本。

### 17.2 通用字段

所有租户业务实体必须包含不可变主键、`tenant_id`、创建人、创建时间、修改人、修改时间和版本号。支持恢复的实体增加删除时间与删除人；历史快照字段不得因主数据改名而变化。

金额使用 `numeric(14,2)` 或等价十进制定点类型，禁止浮点。日期与时间分开建模：团期使用业务日期；操作时间以 UTC 持久化并按 `Asia/Shanghai` 展示。手机号、证件号和邮箱保存原值与展示掩码逻辑，不保存掩码后的覆盖值。

### 17.3 数据库约束

- 所有业务外键必须同时满足租户一致性；应用层校验之外增加数据库约束或事务内校验。
- 订单号在租户内唯一；认证邮箱由 Supabase Auth 全局唯一管理，profile display_name 不是登录标识。
- 应收应付金额、申请金额、已确认金额和在途金额不得为负；冲正使用反向流水，不修改历史流水。
- 审批动作只追加，不更新或删除既有动作。
- 附件对象键全局不可预测，数据库只保存对象键，不保存公开永久 URL。
- 高频过滤字段至少覆盖租户、状态、创建人、负责人、出团日期、审批当前级次和软删除时间的组合索引。

## 19. API 与错误处理约束

### 19.1 API 规则

- 新系统业务接口统一放在 `/api` 命名空间，使用 JSON；文件上传/下载接口不属于首期范围，不实现。
- 列表请求使用明确的 `page`、`page_size`、`sort` 和过滤参数；响应返回数据、总数和当前分页。
- 所有写请求接受 `Idempotency-Key` 或实体版本号；重复键返回首次结果，版本冲突返回 409。
- 创建返回 201，成功读取/更新返回 200，无正文删除返回 204；校验失败返回 422。
- 错误响应至少包含稳定错误码、中文消息、字段错误、请求追踪 ID；不得返回堆栈、SQL 或秘密。

### 19.2 业务错误码

- `AUTH_ACCOUNT_DISABLED`：账号停用。
- `TENANT_SCOPE_DENIED`：租户或数据范围拒绝。
- `ORDER_STATE_CONFLICT`：订单状态不允许该动作。
- `FIN_AMOUNT_EXCEEDS_REMAINING`：金额超过具体项目剩余额度。
- `APPROVAL_STEP_CHANGED`：审批已由他人处理或当前级次变化。
- `OBJECT_REFERENCED`：主数据仍被引用，不能删除。
- `FILE_ACCESS_DENIED`、`FILE_TYPE_INVALID`、`FILE_TOO_LARGE`：未来文件流程的错误类别，随 R-FILE-01 集成任务定义；当前不据此实现 API。
- `IMPORT_ROW_INVALID`：导入行错误，返回行号及字段原因。

### 19.3 文件流程（延期）

文件上传、下载 API 与存储集成不属于首期范围，本期不实现接口或绑定。后续若启动独立文件版本，必须复用会话、租户、功能权限和业务对象授权；该能力不作为当前需求的未完成项。

## 20. 核心事务流程

### 20.1 创建订单

1. 校验客户、线路、供应商与当前租户一致且有效。
2. 服务端计算人数、应收、应付和利润，生成订单号。
3. 在同一数据库事务中写入订单、应收应付项目和审计记录。
4. 本期不创建附件关联；订单核心流程不依赖文件存储。
5. 返回订单详情的权威快照，前端跳转详情页。

验收：重复提交只产生一个订单；篡改前端合计不能改变服务端计算；任一明细失败时不留下半张订单。

### 20.2 创建收付款申请

1. 锁定目标应收或应付项目，计算 `可申请 = 原始金额 − 已确认 − 有效在途`。
2. 校验金额大于 0 且不超过可申请余额。
3. 创建申请、审批实例及第一级待办，并更新在途占用。
4. 写入审计和站内通知后提交事务。

验收：两个并发请求争用同一剩余额度时最多一个成功；失败请求不创建审批或占用。文件关联验收待 R-FILE-01 触发后追加。

### 20.3 审批、驳回与重提

- 通过：锁定审批实例，验证当前级次和权限，追加动作；非终审推进下一级，终审按配置生成确认流水。
- 驳回：要求原因，追加动作并释放在途额度；创建人编辑后重提，生成新的审批轮次，旧动作保留。
- 终审撤回：追加撤回动作，写入反向资金流水，回到终审待办；已完成前级保留。
- 所有动作以事务和版本号防止双击、多人同时审批和重复记账。

### 20.4 订单状态动作

状态命令只允许真源第 3 节定义的迁移。锁团、解锁、转预订单、确认出团、取消和恢复均为独立命令接口，不通过通用编辑接口直接改状态。状态变化必须记录原因、操作者和前后状态。

## 21. 字段校验与导入导出

### 21.1 通用校验

- 文本去除首尾空格；名称为空拒绝，长度上限由数据库与前端一致定义。
- 手机、邮箱和证件号允许业务所需格式，但不把格式合法等同于身份真实。
- 金额最多两位小数；人数和天数为非负整数；回团日期不得早于出团日期。
- 预算上限不得小于下限；线索人数可为 0，订单成人与儿童合计至少 1 人。
- 所有枚举只接受租户内启用值，历史记录显示保存时快照。

### 21.2 游客 CSV

模板固定 UTF-8 BOM，列为姓名、手机、证件类型、证件号、成人/儿童、年龄、性别、备注。上传后先解析预览，不直接落库；返回总行数、有效数、错误数和逐行错误。用户确认后一次事务保存有效数据。首期采用“任一错误则整批不导入”，避免部分成功难以回滚。

### 21.3 订单 CSV 导出

导出继承当前筛选、排序和数据权限；使用 UTF-8 BOM。首期字段按唯一真源第 14 节已抓取的 31 列实现，证件、电话、邮箱按导出权限决定明文或掩码。导出动作写审计，较大导出转异步任务并提供有时效的下载链接。

## 22. 可测量的非功能指标

- **性能**：试运行数据量下，普通列表和详情 API 服务端 P95 小于 800 ms；复杂报表 P95 小于 3 s；超过 3 s 的导出改为异步。
- **容量**：免费阶段数据库达到 400 MB、Workers 达到日额度 70% 时告警并启动升级评估。文件存储不在首期范围，因此本期无对象存储配额目标。
- **恢复**：试运行 RPO 不超过 24 小时，RTO 不超过 4 小时；每月完成一次恢复演练并记录结果。
- **安全**：所有表启用 RLS 或等价租户策略；秘密只存在 Cloudflare/Supabase Secret；依赖漏洞和秘密扫描进入 CI。
- **可观测性**：请求携带追踪 ID；错误率、登录失败、审批冲突、备份失败、容量和健康检查失败产生告警。
- **兼容性**：支持当前及前一个主要版本的 Chrome、Edge；桌面 1366×768 可完成全部 P0 流程。
- **无障碍**：表单控件有标签，键盘可操作，错误不只依赖颜色表达。

## 23. Cloudflare、Supabase 与七牛云实现约束

- Cloudflare Worker 只保存无状态业务逻辑；不得依赖本地磁盘或进程内长期状态。
- Supabase 选择新加坡区域；所有业务表默认拒绝访问，再按租户和角色开放 RLS。
- 浏览器只使用匿名公钥；`service_role` 只能存在 Worker Secret，禁止下发客户端。
- 财务多表写入通过单次 PostgreSQL 函数/RPC 完成，避免多个网络请求形成半完成状态。
- 七牛云为对象存储目标；当前无已确认的前端文件流程，存储集成延期。流程确认后须保持私有/授权访问、租户隔离及不含客户姓名、电话或证件号的对象标识；具体实现和凭证管理另立任务决定。
- 数据库迁移、RLS、函数和种子数据纳入版本控制；生产变更由 CI 执行，不在 Dashboard 手工修改后失去记录。
- 每日健康检查查询专用单行表；每日备份与健康检查是两个任务，健康成功不能替代备份成功。
- 免费服务暂停、限额或网络不稳定时，页面显示维护信息，不允许离线写入后静默覆盖服务器数据。

## 24. 开发阶段与完成定义

### 阶段 0：工程与云环境

建立代码仓库、测试/试运行环境、迁移框架、CI、秘密管理、Supabase、日志、健康检查和备份。七牛云集成不属于阶段 0–5 首期范围。完成条件：从空环境一键部署；备份可恢复；测试与生产配置隔离。

### 阶段 1：认证与基础资料

实现租户、用户、角色、权限、客户、标签、来源、供应商、线路、地区和字典。完成条件：跨租户负向测试通过，快捷新增可供订单调用。

### 阶段 2：订单核心

实现订单表单、金额计算、应收应付、详情、状态机、游客、列表、日历、对账和回收站。附件及七牛云集成不属于首期范围。完成条件：第 12 节第 1、2、4、5、8 项通过。

### 阶段 3：财务审批

实现收付款申请、工作台、驳回重提、两级审批、终审撤回、账户流水、余额和通知。完成条件：并发额度、重复审批和金额回滚测试通过。

### 阶段 4：CRM 与报表

实现线索、跟进、公海、转换、经营分析、业绩、导出和批量结算。目标站 CRM 的 500 错误不得复制。

### 阶段 5：试运行加固

执行权限矩阵、租户隔离、恢复演练、容量、性能、浏览器、敏感信息和完整 UAT；处理试运行反馈后冻结 1.0 范围。

### 单项需求完成定义

每个 `R-*` 只有同时满足以下条件才算完成：数据库迁移与回滚存在；RLS/权限通过；API 和页面状态齐全；审计与错误处理存在；关键业务测试通过；在试运行环境验证；需求编号、测试证据和变更说明可追踪。仅完成页面或返回成功提示不算完成。

## 25. 首期默认业务决定

以下规则构成首期默认需求契约；后续变更通过需求修订和数据库迁移评审执行：

- 币种仅人民币，金额保留两位小数。
- 公司时区固定 `Asia/Shanghai`。
- 审批为财务 → 公司管理员两级，终审自动确认；允许管理员终审自己创建的申请，以匹配已观察行为。
- 终审允许撤回，撤回回到管理员待审并生成反向资金流水；不直接修改原流水。
- 订单存在任何收付款申请时禁止取消；需先驳回或撤回相关申请。
- 游客人数不一致只警告，不阻止保存；订单详情持续显示差额。
- 自动锁团关闭；首期不使用 `to_lock` 状态，锁团/解锁由有权限的用户显式操作。
- 物理删除默认关闭；业务对象使用软删除和恢复。财务、审批、审计不可物理删除。
- 文件能力不属于首期范围，因此首期不定义文件格式白名单、大小限制或上传校验，也不接入七牛云。
- CRM 转客户时按手机号提示重复，由用户选择关联或继续创建；同一线索只能成功转换一次。
- 首期仅站内通知，不发送短信、邮件或企业微信。
- AI 解析不进入 P0；进入后必须先预览，由用户显式确认创建或关联档案。
- 公海线索无有效跟进满 7 个自然日后由每日任务回收；认领、分配和回收均执行原子归属检查。
- 线索阶段配置只影响新建线索；线索阶段历史追加保存。CRM 漏斗展示当前阶段分布，阶段转化率按创建期间 cohort 计算。
- 游客 CSV 用证件类型和规范化证件号识别同订单重复；证件号为空不自动合并，重复行或任一校验错误均拒绝整批导入。
- 订单批量操作逐项校验，部分成功时必须返回每项结果；报表默认按订单创建日期统计，包含预订单、进行中及锁团订单并分状态展示，取消订单默认排除。
- 员工业绩首期按订单创建人归属；财务指标只纳入已确认流水，待审金额单独显示为在途。
- 首期详细模块职责和证据缺口推导规则见[模块化与高性能架构](../.harness/docs/design-docs/functional-modular-architecture.md)第 10 节；功能地图 46 项逐项有对应的实现默认值或首期排除决定。

首期范围闭合决定：提成计算和自组团专项报表不进入首期；结算按供应商、自然月和未结应付明细生成结算批次，实际付款继续走付款申请及审批；退款/更正使用关联原单的部分或全额反向流水，累计冲正不得超过原确认金额，原流水不可修改；审批自审采用本节前述默认规则；数据不自动物理清理，业务记录软删除，财务、审批和审计记录保留；达到 §22 容量告警或性能目标失守时先升级托管资源，再评估国内云迁移。该范围作为首期需求契约，变更通过需求修订和迁移评审执行。

## 26. UAT 验收数据与交付物

UAT 只使用虚构客户、手机号和证件。至少准备两个租户，每个租户包含管理员、计调和财务三类账号，用于隔离和本人/全部范围验证。附件上传/下载不属于首期验收范围。

核心验收数据固定包含：一个 2 成人 1 儿童订单，应收 7,500、应付 4,800；一笔收款 3,000 和一笔付款 4,800；预期利润 2,700、毛利率 36%、客单价 2,500、净现金流 −1,800。该组数据用于订单、审批、余额、报表和导出交叉核对。

最终交付物包括：源码与版本标签、数据库迁移和回滚、环境变量清单、部署脚本、RLS/权限说明、备份恢复手册、管理员使用说明、UAT 结果、已知限制和从免费云迁移到国内云的操作手册。
