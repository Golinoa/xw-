模块依赖与业务链路

以下是按复刻范围归纳的模块关系。箭头表示信息/状态依赖，不表示目标站内部微服务或数据库结构已被证实。

线索、客户与订单主链

线索 / 公海来源、负责人、跟进、阶段
客户与基础资料客户、标签、来源、线路、供应商、地区和字典
订单创建团期、人数、应收应付、利润；正式/预订单
履约管理游客、附件、日历、锁团、取消恢复、对账

财务主链

订单财务项目应收、应付和各项目剩余额度
收款 / 付款申请按订单及明细项目提交；额度在服务端校验
逐级审批审批快照、通过、驳回重提、撤回与审计
内部确认与流水终审自动确认（限实测配置）；不触发银行划款
账户余额 / 结算按已确认收付计算；供应商批量结算另有复核

横切规则

  • 租户与权限：用户/组织上下文与权限检查覆盖每次读写、导出、附件访问；数据库 RLS 是第二道隔离。第二租户与 own/all 数据范围仍需验证。
  • 审计：审批、金额、状态、权限、配置和删除恢复等高影响行为要留操作者、对象、前后状态/摘要。
  • 通知：审批待办、驳回、临期、出团与跟进提醒；目标站完整投递链仍待补测。
  • 设计框架：全局顶栏 + 左侧菜单 + 右侧工作区，首页工作台使用仪表盘；这是本项目已定设计约束，不等同于调研证据。

数据所有权边界

  • 订单是业务聚合中心；游客、附件、应收应付项目和收付记录围绕订单关联。
  • 收付款终审、余额和审计必须保持事务一致；重复提交与并发额度不可由页面状态代替校验。
  • 客户/线路/供应商等快捷新增仍是订单创建过程中的关联主数据能力，不应变成彼此重复的第二套数据源。
  • 报表、工作台、导出应复用相同筛选口径和数据范围；不要从目标截图臆造指标。

范围缺口、未决事项与明确排除

这些事项会影响模块设计或实现顺序，不能在拆分图中悄悄填成既定规则。

需补测 / 需业务定规则

  • 第二租户、同角色本人/全部数据范围，以及同租户对象、附件、导出授权。
  • CRM 的编辑、查重、公海认领/分配、转客户/订单、完整阶段漏斗；目标站创建线索出现 HTTP 500，不能复制该缺陷。
  • 订单金额总价覆盖、动态应收应付异常组合、服务端重算；并发状态转换和锁团后服务端编辑保护。
  • 收付款审批配置变更、关闭自动确认、自审策略、撤回/冲正、重复提交/并发审批；批量结算重复纳入和月结规则。
  • 通知投递与已读链路、导入模板和逐行失败、导出内容及权限过滤、附件对象级权限。
  • 订单与报表状态统计口径、CRM 有数据后的统计、筛选下钻、公司设置完整保存效果。
  • AI 解析对目标站会自动创建客户与线路；复刻建议改为“先生成建议、人工复核、显式关联/创建”。这是产品方案建议，需在需求定稿时明确。

当前范围外 / 不可从证据推出

  • 真实银行划款、第三方支付、外部短信/邮件/企业微信、OTA 下单、电子合同签署、多币种核算：现阶段需求明确排除。
  • 七牛云是对象存储目标，但目前无确认的持久化前端上传/下载流程，集成暂缓；不作为阶段 0 或订单主链前置。
  • 原目标站的真实数据库 schema、租户模型完整细节、套餐计费行为没有证据；本项目可自行设计，但须建立自己的迁移与验收。
  • AI 模型供应商、提示词、额度、流式对话、多智能体编排、工具执行均未证实；AI_PARSE 与 AI_CRM 不等于 Agent 对话模块。
  • 参考图能支撑视觉方向与布局结构，不能证明目标站每个功能的像素尺寸、断点或未展示业务行为。
