## 踩过的坑（下次直接照做）

1. **`nullif` 不能写 `pg_catalog.nullif`** —— 它是 SQL 构造不是 catalog 函数，
   写了会让所有在审计表写行的既有测试崩掉（一次暴露 10+ 个失败）。
2. **JSON header 解析的 `split_part(..., '"', 2)`** —— 第 1 段是空串（因为值以引号开头），
   真正的字段值在第 2 段；`x-forwarded-for` 有多个 IP 时还要再取逗号前第一个。
3. **`SET LOCAL ROLE authenticated` 下不能直接 UPDATE 业务表** —— 要走 SECURITY DEFINER 的 RPC
   （`transition_order_status` / `update_order_with_items`），否则 `permission denied`。
4. **测试间数据污染**：C10 的 HTTP 测试为造审计去改公司配置，把 C12 测试硬编码的版本号
   0/1/2 全打乱（全量跑 4 条红）。修法是让 C12 测试改成读当前版本做相对断言，
   两个测试互不假设对方没跑过。⇒ 规则：集成测试永远不要假设数据库初始状态。

## 边界

- 审计**只有读端点，没有任何写/删端点**——能改的日志不是证据。
- 写入失败不绑架业务：函数在无组织上下文时直接返回，业务照常成功。
- 尚无"审计对账"任务发现漏记，触发器覆盖的是三类强制动作 + 已有成员/配置动作。
