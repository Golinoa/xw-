# 有单 OMS 交互反馈与动效规范

> 状态：已定稿　|　适用范围：有单 OMS Web 管理后台　|　生效日期：2026-10-05

## 快速规则

- 每个用户操作都要有可感知结果：即时状态、处理中、成功或可恢复的错误。
- 参考界面以静态状态为主，可见当前导航、任务进度和语意状态；截图不能确定具体过渡效果，因此动效采用克制、快速、可关闭的项目规则。
- 动效只说明状态变化或空间关系；不延迟操作，不装饰性循环，不制造误导。
- 尊重系统“减少动态效果”设置，并确保无动画时信息和操作仍完整。

## 1. 交互状态

| 状态 | 呈现要求 |
|---|---|
| 默认 | 文案、控件边界和可操作范围清晰 |
| Hover | 桌面指针操作提供轻微背景/边界变化，不改变布局 |
| Focus | 键盘焦点显示清晰外框；不以 hover 代替 |
| Pressed | 短暂强调按下反馈，不移动周围内容 |
| Loading | 明确忙碌对象；防止重复提交；无关区域保持可用 |
| Disabled | 使用中性弱化并表达不可用原因；禁用不能伪装成加载 |
| Success | 说明已完成事项；短暂提示不遮挡后续工作 |
| Warning/Error | 说明问题、影响和下一步；可恢复错误提供重试或修正入口 |

状态颜色遵循色彩规范。状态变化使用文字、图标或控件行为共同表达，不能只依赖颜色。

## 2. 反馈层级

- **字段校验：** 错误紧邻字段，说明如何修正；提交后保留已输入内容。
- **局部操作：** 短暂成功/失败反馈使用 Message 或控件内状态，避免同时弹出多种重复通知。
- **持续问题：** 页面级 Alert 展示影响范围和可行操作，问题解除后同步清除。
- **重要异步事项：** Notification 提示完成或失败，并链接回对应业务对象。
- **需要决策：** Modal 用于不可逆或会中断当前流程的确认；一般信息不使用弹窗打断。
- **长时间任务：** 显示阶段或进度；未知百分比时使用不确定进度，不伪造百分数。

## 3. 动效时长与行为

| 动效 | 建议时长 | 规则 |
|---|---:|---|
| Hover、焦点、按下 | 100–150ms | 仅颜色、边界或透明度轻微变化 |
| 小型状态切换 | 150–200ms | 用于标签、折叠或选中反馈 |
| Drawer、Popover 等空间过渡 | 180–240ms | 方向与出现位置一致，不阻塞可见操作 |
| 加载指示 | 持续到任务结束 | 避免无意义循环；提供可访问状态文本 |

- 默认使用 ease-out 进入、ease-in 离开；不通过弹跳、缩放或大幅位移吸引注意。
- 动效不得导致内容位移、闪烁、重复触发或焦点丢失。
- 关闭、撤销等即时操作不等待过渡完成后才生效。
- CSS 过渡集中使用组件库能力或共享变量，不为单个页面散落自定义时间值。

## 4. 加载与异步反馈

- 初次加载使用骨架或区域级 Loading，避免整个页面闪白；已加载内容在刷新时尽量保留。
- 提交操作立即反馈并防止重复提交；超时或失败后恢复可重试状态。
- 乐观更新仅用于可安全回滚的操作；失败时恢复原值并告知结果。
- 长任务提供进度、阶段或明确的“仍在处理”提示；完成或失败后更新状态并允许继续操作。
- Loading 状态提供辅助技术可读文本，如“正在保存”。

## 5. 键盘、减少动态效果与可访问性

- 所有操作可通过键盘到达；焦点顺序符合页面阅读顺序，弹层打开后焦点进入弹层，关闭后返回触发位置。
- 焦点样式满足非文本对比度要求，不得被裁切、遮挡或覆盖。
- 对 `prefers-reduced-motion: reduce`，将非必要过渡缩短至近乎即时，移除位移、缩放和循环装饰。
- 对成功、错误和进度变化使用适当的辅助技术播报；避免高频播报图表动画或重复消息。
- 触控设备不依赖 Hover 才能显示操作。
