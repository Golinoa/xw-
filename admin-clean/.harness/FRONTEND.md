# 前端约束

## 确认的前端方向

使用官方 Vue Vben Admin v5 `apps/web-antd` 为独立前端底座。它依赖根 workspace 内多个 `@vben/*` 包；必须保留 monorepo 结构并锁定上游 commit。业务需求见 `Docs/PRD.md`；Vben 只提供后台框架，不替代业务服务。

## 组件、状态和请求

- 页面按业务域组织，表单/列表/详情承载具体工作流；只在存在真实复用或统一行为时抽取组件。
- 使用统一 API client 调 Hono 端点；运营权限必须由 API/RLS保障，菜单/路由/按钮隐藏只是用户体验。
- 前端只保存公开 Auth URL/key 和用户 session；不把 Supabase service role、DB credential 或对象存储 secret 放入变量/构建文件。
- 记录状态语义以共享契约为准，展示标签与机器状态分离；非法响应不能兜底为成功或有效状态。
- 所有页面显式实现加载、空、错误、验证、无权限、无数据和高影响动作确认状态。
- 列表必须服务端筛选和分页；不在浏览器下载全部客户、合同或账款后筛选/聚合。
- 页面视觉遵循根 `DESIGN.md` 和共享已定稿设计系统；Vben 默认主题须映射到统一 token。

## 路由与权限

- 菜单和动态路由声明只使用稳定权限名；路由守卫是界面保护，不替代 API 鉴权。
- 无运营成员关系的用户在导航完成前拒绝加载业务模块，并由后端再次拒绝所有请求。
- 退出或停用后清理缓存的用户状态；不得在本地持久化运营 bearer token 到非安全存储。
