# API 与权限约束

- 运营 API 由 `udone` Hono 后端唯一拥有；实际路由与请求/响应字段先在后端真源定义，`~admin` 只消费已发布契约。
- 新运营端点使用 PRD 约定的独立版本化命名空间；在代码中确认现有路由前，不虚构或发布 API 字段。
- 路由入口验证路径、查询、header 和 JSON；TypeScript 声明不能替代运行时验证。
- 每个查询、写入、导出和附件操作都在服务端验证 Auth、有效运营成员关系、明确权限及目标资源归属。
- `userId`、角色和运营上下文来自已验证身份/数据库成员关系，不能接受客户端自报 owner 或权限。
- 错误遵循后端现有稳定契约，包含安全消息和 request ID；不返回 SQL、堆栈、完整 token 或未经脱敏的上游错误。
- 列表必须有有界分页、确定性排序和服务端筛选；查询不得一次加载全量商业记录。
- 合同、收款、退款、授权和租户写操作说明事务、冲突和重放行为；多表不变量在同一数据库事务或受控幂等命令中完成。
- 跨系统命令使用唯一幂等键、关联商业对象和可查询状态；网络超时后先查命令状态再重试。
- 兼容变更同步更新 API 真源、消费者契约和测试；不依赖猜测现有 `udone` 表字段。
