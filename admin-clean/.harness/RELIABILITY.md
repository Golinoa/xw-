# 可靠性约束

- 所需 API/Auth/数据库不可用时明确失败；健康端点不得暴露 secret、SQL 或客户资料。
- 只对已定义为暂时错误且可安全重复的操作使用有界重试；财务、退款、租户和权益命令必须先具备幂等键与可查询结果。
- 跨系统超时不能推断失败或成功；先检查幂等命令状态后重试，并使用退避/上限/永久错误分类。
- 相关账务和权益状态变化保持事务一致；审计记录同业务事务或通过可靠 outbox 持久化。
- 日志提供 request ID、关联对象 ID 和错误类别，不包含认证信息、支付 secret 或完整客户资料。
- 失败命令可被识别、重试或人工终止；重试操作记录操作者和原因。
- 运行时容量、恢复目标、重试队列和告警策略需按当前 Cloudflare/Supabase 配置实证，不将计划目标写成已实现的 SLA。
